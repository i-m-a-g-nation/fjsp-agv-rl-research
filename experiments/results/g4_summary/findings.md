# G4 结论：周期性预防维护下 RL 与搜索算法的质量—时间对比（2026-10-31）

协议：[docs/protocols/g4_periodic_protocol.md](../../../docs/protocols/g4_periodic_protocol.md)（批准后、运行前的修正和执行中的计时问题见其第 7、8 节）。
数据：576 个测试实例（288 个案例 × 固定/联合）。每个实例的 best-known 取所有方法、所有运行中的最小总延期；
gap = (T − best-known) / max(1, best-known)。

## 计时与公平性

- 搜索算法（IGA、SA）的计时来自 [g4_search_curves_retimed](../g4_search_curves_retimed/)：机器上没有其他负载，2 个进程并行。
  抽样核对，其解码速度与单独运行基本相同（中位比值 n=50 为 1.03，n=100 为 1.01）。
- 第一次搜索运行（[g4_search_curves](../g4_search_curves/)）与 RL 训练同时进行，IGA 的解码速度约慢 1.75 倍，会偏向 RL。
  因此只采用其中的规则、GA 和 CP-SAT；这三者的计时不是比较重点。
- RL 计时（[g4_policy_curves](../g4_policy_curves/)）：一次一个实例，计入特征计算、环境推进和最终检查。
  - `RL`：GPU（RTX 4060 Laptop），先贪心 1 次，再采样 4/16/64 次取最好；
  - `RL-cpu`：单线程 CPU，贪心和采样 4 次。
- 硬件：i7-13700H。只有一个训练种子；搜索算法只用种子 0。

## 预先登记的假设

| 假设 | 结果 |
|---|---|
| **H1**：n ≥ 50、t ≤ 0.2 s 时，RL（GPU 计时）优于 IGA/SA/GA | **不成立**。GPU 上单次贪心的中位耗时 n=50 为 0.15 s、n=100 为 0.32 s，所以 t = 0.05/0.1 s 时 RL 还没有解。t = 0.2 s（只有一半实例有解）：与 IGA 无显著差异（38/105/48，p = 0.23），优于 SA（p = 0.002）和 GA。 |
| **H2**：t ≥ 2 s 时 IGA/SA 优于 RL | **部分成立**。2 s 时恰好相反，RL 优于 IGA（p = 0.012）和 SA（p = 2e-10）；5 s 时无显著差异；10 s 时 IGA（p = 0.0015）和 SA（p = 9e-7）优于 RL。 |
| **H3**：协同维护降低总延期 | **成立**，见下文。 |

## 按规模的探索性比较（看到上述结果后才增加的分析）

平均 gap（越小越好）：

| 规模 | 时间 | MDD | SA | IGA | RL（GPU） | RL（CPU） |
|---|---|---|---|---|---|---|
| n=20 | 0.5 s | 2.316 | **0.011** | 0.037 | 0.066 | 0.125 |
| n=20 | 10 s | 2.316 | **0.001** | 0.025 | 0.065 | 0.125 |
| n=50 | 0.5 s | 0.504 | 0.116 | 0.070 | **0.058** | 0.087 |
| n=50 | 2 s | 0.504 | 0.044 | 0.037 | **0.036** | 0.087 |
| n=50 | 10 s | 0.504 | **0.002** | 0.019 | 0.036 | 0.087 |
| n=100 | 0.2 s | 0.374 | 0.446 | 0.065 | —（无解） | **0.023**（92%） |
| n=100 | 0.5 s | 0.374 | 0.257 | 0.041 | **0.023**（92%） | 0.024 |
| n=100 | 1 s | 0.374 | 0.138 | 0.028 | **0.009** | 0.014 |
| n=100 | 2 s | 0.374 | 0.050 | 0.020 | **0.006** | 0.013 |
| n=100 | 10 s | 0.374 | 0.008 | 0.006 | **0.004** | 0.013 |

配对检验结果：

- **n = 100**：RL 在 0.5–2 s 内显著优于 IGA（p ≤ 3e-6）和 SA（p ≤ 2e-14）。单线程 CPU 推理 0.2 s 就有解（覆盖 92% 的实例），优于同一时刻的 IGA（60/107/9，p = 2e-9）。
  10 s 时 RL 的平均 gap 仍然最小（0.004 vs 0.006），这一点未做检验，只作描述。
- **n = 50**：RL 与 IGA 在 0.2–2 s 内都没有显著差异，在 0.2–1 s 内优于 SA。10 s 时 SA 和 IGA 更好。
- **n = 20**：SA 和 IGA 一直最好；RL 很快就停在 gap ≈ 0.065。

**结论**：RL 的优势出现在大规模（n = 100）、0.2–2 s 的时间预算内，而不是预先设想的"极短时间"。
原因是单次推理（尤其在 GPU 上）就需要 0.15–0.3 s；而搜索算法每次解码的代价随规模增大，同样时间内能完成的评估次数在 n = 100 时明显减少。
小规模、长时间时，IGA/SA 更好。
另外，单实例推理在 CPU 上比 GPU 更快（GPU 的固定开销在小批量时占主导）；部署时用 CPU 推理反而能把 RL 的曲线左移。

## H3：协同维护的作用

以每个实例的 best-known 计算，只统计固定方案下延期大于 0 的配对：

| 分组 | 配对 | 平均相对降低 | 联合更好 / 更差 |
|---|---:|---:|---|
| n = 20 | 69 | 49.4% | 69 / 0 |
| n = 50 | 44 | 10.7% | 29 / 0 |
| n = 100 | 40 | 6.9% | 31 / 1 |
| 窗口余量 β = 25% | 78 | 23.6% | 63 / 1 |
| 窗口余量 β = 50% | 75 | 30.9% | 66 / 0 |
| 维护时长 α = 10% | 69 | 29.9% | 54 / 1 |
| 维护时长 α = 20% | 84 | 25.0% | 75 / 0 |
| 周期 uniform2 | 77 | 28.1% | 69 / 0 |
| 周期 mixed | 76 | 26.3% | 60 / 1 |
| 交期 τ = 75（紧） | 132 | 19.9% | 108 / 1 |
| 交期 τ = 125（松） | 21 | 73.2% | 21 / 0 |

窗口越宽，协同收益越大，与单窗口 G3A 的结论一致。规模越大，相对收益越小，因为延期主要来自总负荷而非维护位置。
唯一一个"联合更差"的配对（n = 100）是搜索限时造成的：联合的可行域包含固定的可行域。

## 局限

- n ≥ 50 时 CP-SAT 很弱，所以 best-known 主要来自 IGA/SA/RL，gap 是相对"已找到的最好解"，不是相对最优解。
- 只训练了一个 RL 模型（一个种子），搜索算法只跑一个种子，都在一台笔记本上计时。
- 平均 gap 会被 best-known 很小的实例放大，配对检验（基于秩）不受此影响。
