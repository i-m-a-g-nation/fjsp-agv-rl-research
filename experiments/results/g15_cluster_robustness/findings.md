# G15 结论：按基础数据聚类的稳健性检验与 G4 的 Holm 校正（2026-11-07，探索性）

- 脚本：[`experiments/g15_cluster_robustness.py`](../../g15_cluster_robustness.py)，提交 `cc1fd08`，`git_dirty` 为 false；
  `summary.json` 记录源码哈希（含被导入的 `g9`、`g12`）和全部输入文件的哈希。
- **看到全部结果之后才做的事后分析**，只读已归档的结果行，不求解、不训练、不计时；不改变任何预先登记的结论，
  只说明这些结论在统计上能推广到多远。2026-11-07 经用户同意进行。
- 每个预先登记的检验先按归档方式在实例层面重算，与归档的 p 值、胜/平/负逐项核对（不一致就中止）；全部一致。
- 输出：`tests.csv`（每个检验一行）、`clusters.csv`（每个检验的每个簇一行）、`summary.json`。

## 为什么要做

测试实例共用基础数据，归档的 Wilcoxon 检验却把每个实例当作独立样本：

| 研究 | 簇（基础数据） | 簇数 |
|---|---|---|
| G4、G5-T | `(n, 实例种子)`：加工时间和交期分位数只由它决定，48 个案例 × 固定/联合共用 | 6（n ≥ 50 为 4，n = 100 为 2） |
| G5-L | 同上，n = 200 | 2 |
| L2 | 基准算例：每个算例 5 种配置 | T1 10、T2 6、合计 16 |

实例层面的检验回答"在这几组基础数据、各种因子设置下是否更好"；簇层面的检验回答"换一组新的随机基础数据是否还会更好"。

## 方法

- 每个簇取配对差值（方法 − 对照）的平均，每个簇算一票，与簇内实例数无关。
- **精确符号翻转检验**：在"没有差别"的假设下每个簇均值取正取负的可能性相同，枚举全部 2^k 种符号，
  单侧、按预先登记的方向。k 个簇时 p 最小只能到 2^−k：2 簇 0.25、4 簇 0.0625、6 簇 0.0156、16 簇 1.5e-5。
- 与 G5、L2 的协议一致：每个训练种子内对该研究的全部假设做 Holm 校正，α = 0.05；3 个种子中至少 2 个满足才算成立。
- G4 另补协议当时没有实现的部分：实例层面按登记方向做单侧 Wilcoxon，H1 族（9 个检验）按登记的 α = 0.01 做 Holm，
  H2 族（6 个）按 α = 0.05 做 Holm（协议没有给 H2 阈值）；24 个事后检验沿用归档的双侧 p 值，族内 Holm。

## 结果

### 簇层面

| 研究 | 假设 | 方向一致的簇（3 个种子） | 每种子 Holm 后成立的种子数 | 实例层面（归档） |
|---|---|---|---|---|
| G5 | H1 RL < IGA，n = 100，1 s | 2/2、2/2、2/2 | 0（2 簇，p ≥ 0.25） | 3 |
| G5 | H2 RL 贪心 < 只模仿 | 6/6、6/6、6/6 | 0（p = 0.0156，×5 后 0.078） | 3 |
| G5 | H3 RL + IGA < IGA，10 s | 5/6、6/6、6/6 | 0 | 3 |
| G5 | H4 RL + IGA < IGA，1 s | 5/6、5/6、5/6 | 0 | 3 |
| G5 | H5 RL < IGA，n = 200，2 s | 1/2、1/2、1/2 | 0 | 2 |
| L2 | H1 贪心 < EFT | 13/16 × 3 | **3** | 3 |
| L2 | H2 采样 32 < 逐实例最好规则 | 16/16 × 3 | **3** | 3 |
| L2 | H3 采样 32 < 等时 SA，T2 | 6/6 × 3 | **3** | 3 |
| L2 | H4 采样 32 < 等时 SA，T1 | 7/10 × 3 | 0（p = 0.053–0.090） | 3 |

- **G5 的五个假设在簇层面都不成立，但这是设计决定的，不是数据显示相反**：只有 2–6 组基础数据，
  即使所有簇方向一致，Holm 后 p 也不可能低于 0.05。H1–H4 的方向在几乎所有簇上一致，可以写"方向在每组基础数据上都一致"，
  不能写"可推广到新的随机数据"。
- 方向不一致的簇：
  - H3 种子 0、H4 全部种子：唯一的反例都是 `n20-s1004`，即 n = 20 时 RL + IGA 不一定比 IGA 好，与"小规模搜索更强"一致；
  - **H5 只靠一组数据**：`n200-s1003` 上 RL 更好（gap 差约 −0.034），`n200-s1004` 上 RL 更差（+0.06 / +0.07 / +0.25），
    与 G5 findings 中"几乎无延期的实例上偶尔多出几个单位"一致。H5 应写作最弱的结论。
- **L2 的 H1–H3 在簇层面仍然成立**（16 个或 6 个算例足够）；**H4 不成立**：fjsp3、fjsp8、fjsp9 三个算例在所有种子上
  都是 SA 更好，其余 7 个是策略更好。所以"小算例上同等时间优于 SA"取决于算例，应降级为描述性结论。

### G4 的 Holm 校正（实例层面，单侧，登记方向）

| 假设 | 预算 | 对照 | 胜/平/负 | Holm 后 p | 成立 |
|---|---|---|---|---|---|
| H1 RL < 对照（α = 0.01） | 0.05、0.1 s | IGA/SA/GA | RL 还没有解 | 1 | 否 |
| | 0.2 s | IGA | 38/105/48 | 1 | 否 |
| | 0.2 s | SA | 55/106/30 | 0.0064 | 是 |
| | 0.2 s | GA | 96/95/0 | 8.0e-17 | 是 |
| H2 对照 < RL（α = 0.05） | 2 s | IGA / SA | 80/243/61、106/238/40（RL 胜多） | 1 / 1 | 否 |
| | 5 s | IGA / SA | 60/251/73、68/246/70 | 1 / 1 | 否 |
| | 10 s | IGA / SA | 44/247/93、41/245/98 | 0.0037 / 2.7e-6 | 是 |

- 0.2 s 时 RL 只在 n = 50 上有解（191 个实例、2 个簇），所以 H1 实际只覆盖 n = 50。
- 结论与归档的"H1 不成立、H2 部分成立"一致，现在有了校正：H1 只在 0.2 s 对 SA、GA 成立，对 IGA 不成立；H2 只在 10 s 成立。
- 归档 findings 中"2 s 时 RL 优于 IGA（p = 0.012）"与 H2 的登记方向相反，是看到结果后才换的方向：
  按双侧在 H2 的 6 个检验内做 Holm 为 0.036（对 SA 为 1.4e-9），只能作为事后观察。
  24 个事后检验（族内 Holm）中，n = 100、0.5–2 s 时 RL 优于 IGA 和 SA 的 6 项 Holm 后都 < 1e-4；
  n = 50、2 s 时 IGA 优于单线程 CPU 上的 RL（Holm 后 5e-4）。这些仍是事后、实例层面的结论。
- G4 的簇层面：H1 只有 2 簇、H2 只有 4 簇，在 α = 0.01 / 0.05 下都不可能成立（`tests.csv`）。
  2 s 时 RL 对 SA 在 4 个簇上都更好，对 IGA 3/4 个簇更好。

## 对论文写法的影响

1. 毕设第 5 章：G5 的 H1–H4 写成"在 G5 的 6 组基础数据、各种维护与交期设置下，配对检验显著，且方向在每组基础数据上一致
   （H4 在 n = 20 的一组上例外）"；同时说明基础数据只有 6 组，不能按独立实例推广。H5 写成最弱的、只在一组数据上成立的结论。
2. G4 的 H1/H2 按本表的校正结果报告。
3. 大创论文：H1–H3 可以照常写（簇层面仍成立）；H4 改为"7/10 个小算例上更好，3 个算例上 SA 更好"。
4. 如果以后要真正检验推广性，需要更多的实例种子（例如每个 n 用 20 个以上种子），这属于新的实验批次，需要另行批准。
