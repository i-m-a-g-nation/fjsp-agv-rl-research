## 算法（`src/graduation/metaheuristics.py`）

- **编码**：n 个工件和 m 个维护标记组成的一个排列。
- **解码**：从左到右读排列。
  - 工件放到最早完工的机器上。若这台机器还没维护，只有加工完后维护仍能放进窗口时，工件才排在维护前；否则先插入维护，再排工件。
  - 读到维护标记就安排该机器的维护：固定模式在 f_i，联合模式在 max(机器空闲时刻, L_i)。
  - 这样解码出的计划一定满足维护窗口，搜索中不需要修复或罚函数。解码器没有规模上限。
- **三种算法**，预算统一按"解码次数"计，局部搜索的解码也算在内：
  - **GA**：随机初始种群 40，锦标赛选择，顺序交叉（OX），交换或插入变异，保留 2 个精英。
  - **SA**：从 EDD 顺序出发，交换或插入邻域；初温按"一半的变差移动被接受"标定，几何降温到初温的千分之一。
  - **IGA（改进 GA）**：GA 加上 6 个启发式初始解（EDD、SPT、最小松弛三种顺序 × 维护标记放最前或最后），每代对最好个体做 20 次插入局部搜索。
- 每个返回的计划都在求解函数内部通过 G1 检查器，并独立重算总延期。

## 协议（全量运行前固定）

- **实例**：exp_038 的 G3A 网格 480 个（主网格 160 对 + 敏感性 80 对，固定和联合各一）。
- **预算**：1 000、10 000、50 000 次解码；每个（实例、算法、预算）跑 5 个种子（0–4），报告均值。
- **参数**：全部用代码中的默认值，没有调参。全量运行前只做过一次试跑：在 20 个 n=24 主网格实例上（种子 0）看预算量级，之后没有改任何参数。这 20 个实例也在本次 480 个之内，特此说明。
- **对照**：规则、策略 `policy_s0`（exp_038 选定的最终模型）、CP-SAT 1 秒和 60 秒，都读 exp_038 归档值。
- **安全检查**：任何结果若低于已证得的最优值，运行立即停止。实际没有触发。

## 结果

### 1. 总体（480 个实例，5 种子均值）

| 方法 | 平均总延期 | 距已知最好 | 达到已知最好 | 单实例耗时 |
|---|---:|---:|---:|---:|
| MDD | 27.81 | 5.36 | 235 | — |
| 9 规则组合 | 24.30 | 1.85 | 316 | 19 ms（9 个合计） |
| 策略 1 次回放 | 25.58 | 3.14 | 279 | 10 ms |
| 策略 9 次回放 | 23.97 | 1.52 | 318 | 82 ms |
| GA 1k / 10k / 50k | 26.06 / 23.45 / 23.17 | 3.62 / 1.00 / 0.72 | 342 / 399 / 412 | 14 / 117 / 575 ms |
| SA 1k / 10k / 50k | 23.66 / 22.69 / 22.54 | 1.22 / 0.25 / 0.10 | 399 / 434 / 454 | 8 / 72 / 357 ms |
| IGA 1k / 10k / 50k | 23.33 / 22.74 / 22.61 | 0.88 / 0.29 / 0.16 | 393 / 429 / 441 | 11 / 101 / 498 ms |

耗时是 4 个进程并行时测得的单线程时间，只能作量级参考。规则和策略的耗时取自 exp_038。

### 2. 改进 GA 的消融（IGA vs GA，相同预算）

| 预算 | 全部 480 | n24-m2 | n24-m4 |
|---|---|---|---|
| 1k | −10.5%（p=5e-23） | −18.1% | −20.1% |
| 10k | −3.0%（p=2e-12） | −4.5% | −7.9% |
| 50k | −2.4%（p=4e-12） | −3.5% | −6.7% |

启发式初始解加局部搜索带来稳定改进，预算越小、规模越大越明显。n=8 上三者都几乎每次找到最优，差别很小。

IGA 和 SA 比：1k 预算下 IGA 好 1.4%（p=2e-4）；10k 时持平（p=0.88）；50k 时 SA 略好 0.3%（p=9e-4）。

### 3. 和 CP-SAT 比（n=24 主网格，160 个实例）

| 规模 | CP-SAT 60 秒（4 线程） | SA 50k | IGA 50k | GA 50k |
|---|---:|---:|---:|---:|
| n24-m2 | 36.34 | 36.33（持平） | 36.52（+0.5%，p=0.79） | 37.84（+4.1%） |
| n24-m4 | 27.46 | 27.28（−0.7%，p=0.69） | 27.48（+0.1%，p=0.15） | 29.46（+7.3%） |

SA 和 IGA 用约 0.4–0.5 秒单线程，达到 CP-SAT 60 秒 × 4 线程的水平，差别不显著；本实验还在 14 个实例上刷新了已知最好解。n=8 上，SA/IGA 10k 以上全部达到证得的最优值。

### 4. 和学习型策略比（重要）

| 对照 | 差别 | 胜 / 平 / 负 | p 值 |
|---|---|---|---|
| IGA 1k（约 11 ms）vs 策略 9 次回放（约 82 ms） | −2.7% | 142 / 306 / 32 | 2e-13 |
| IGA 10k vs 策略 9 次回放 | −5.1% | 157 / 314 / 9 | 2e-26 |
| 策略 1 次回放（约 10 ms）vs IGA 1k（约 11 ms） | +9.7% | 17 / 273 / 190 | 2e-27 |

**在这批静态实例上，相同墙钟时间下，智能优化算法明显好于学习型策略。** exp_038 中"策略的价值在于毫秒级速度"的定位，在加入智能优化算法后不再成立：IGA 用差不多的时间就给出更好的解。只有 n24-m2 上 IGA 1k 和策略 9 次回放持平（p=0.37）。

### 5. 固定 vs 联合维护：按因子分解

用每个实例的已知最好解（所有方法的最小值）比较。n=8 的 160 对全部证得最优；n=24 是目前最好的上界。全部 240 对中，联合从没比固定差（理论上也不应该），有 135 对严格更好。

| 分组 | 固定 | 联合 | 平均相对降低 |
|---|---:|---:|---:|
| n=8 主网格（80 对，全部证得最优） | 27.55 | 14.71 | 54.0% |
| n=24 主网格（80 对） | 37.95 | 25.07 | 35.5% |
| 窗口宽度 β=25%（n=8 / n=24） | | | 40.9% / 6.9% |
| 窗口宽度 β=75%（n=8 / n=24） | | | 67.5% / 64.0% |
| 维护时长 α=10%（n=8 / n=24） | | | 52.0% / 33.7% |
| 维护时长 α=30%（n=8 / n=24） | | | 55.7% / 36.7% |
| 交期 τ=75%，偏紧（n=8 / n=24） | | | 42.1% / 35.5% |
| 交期 τ=125%，宽松（n=8 / n=24） | | | 74.6% / 全部为 0 |
| 固定在窗口最早 / 最晚（n=8 敏感性组） | | | 44.6% / 30.5% |

相对降低只在固定方案延期大于 0 的配对上平均。

- **窗口宽度是最关键的因素**：窗口宽时，联合决定维护时机的空间大，降低 64%–68%；窗口窄时只有 7%–41%。
- **维护时长主要放大绝对延期**：α 从 10% 到 30%，n=24 的固定延期从 7.4 增加到 68.5，但相对降低差不多（34%–37%）。
- **交期宽松时**，n=24 的固定和联合都能做到零延期；n=8 时联合几乎消除了延期（9.50 → 2.52）。
- **固定方案的选法影响收益**：固定在最晚时联合的额外收益最小（30.5%），固定在最早时最大（44.6%）。

## 结论

**能说**：
- 三种智能优化算法都能在毫秒到亚秒级给出合法的高质量解。改进 GA 比标准 GA 稳定更好，消融实验支持"启发式初始解 + 局部搜索"的作用。
- SA 和 IGA 用 0.4–0.5 秒，在 n=24 上达到 CP-SAT 60 秒 × 4 线程的水平；n=8 上达到证得的最优值。
- 协同维护在证得最优的 n=8 上把总延期降低 54%，n=24 上（已知最好）降低 35.5%；窗口越宽收益越大。

**不能说**：
- 学习型策略在这批静态实例上**不再有速度—质量优势**：相同时间下 IGA 更好。论文里 RL 不能再以"快速近似"作卖点，需要新的定位（见下）。
- n=24 的已知最好解不一定是最优；n 最大 24，没有检验更大规模。
- IGA 和 SA 在大预算下基本持平，"改进 GA 优于 SA"只在小预算下成立。
- 这不是课题最终验收。research_status 仍为 not_achieved。

## 对论文结构的影响（需要用户和导师决定）

1. **智能优化算法作为主方法**：IGA 是本问题上最实用的方法，RL 作为对照和探索。这样最贴合实验事实。
2. **把两条线结合**：用学习型策略生成 IGA 的初始解（RL + IGA 混合）。这是有可能的创新点，但需要新实验验证收益。
3. **转到 RL 更有优势的场景**：动态重调度、大规模、需要反复求解的场合（候选创新 I4）。但 IGA 在 1k 预算下只要约 11 毫秒，RL 在动态场景下也未必占优，需要实验确认。
