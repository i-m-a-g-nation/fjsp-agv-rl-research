# 毕设生产—维护协同：首版模型与 G1 实现范围

状态：**G1 基础及用户随后以“开始”放行的 G2 小规模参考求解已实现**。2026-10-25用户选择优先毕设，确认同质机器、每机一次必需维护及完整维护区间在窗口内，随后明确批准单工序、全部任务0时刻到达、无共享维修班组的首版范围。这是当前 Phase2A 的特定实施例外；本文不修改 AGENTS、研究契约或运行会话的人审决定。首版简化仍是研究设定，不是完整任务书或现场已证明的事实。

## 1. 依据与目标

直接依据是用户提供的毕设课题描述截图，内容要求：以平行机车间为对象，考虑加工时间、交期、维护时长及允许维护时间窗口；联合优化任务分配、加工顺序和维护时机；以最小化总延期为目标；在不同规模和维护条件下比较固定维护安排与协同方案。截图未给出完整任务书、机器同质性、维护次数或时间窗端点含义。

本草案先给一个可精确验证的小模型，再确定最终研究算法。CP-SAT只作为小规模参考基线；完整任务书是否明确要求强化学习或特定智能算法，仍须确认。大创申请书的生产—物流/AGV/RL目标与本模型分开验收。

## 3. 变量与模型

任务集合J={0,...,n-1}，机器集合I={0,...,m-1}，n,m>=1。输入为p_j>0、d_j>=0、q_i>0、0<=L_i<U_i，且q_i<=U_i-L_i。所有值为整数。

- x_ji∈{0,1}：任务j分配到机器i。
- s_j>=0，C_j=s_j+p_j：任务开始与完成。
- M_i：机器i必需维护的开始时刻，结束为M_i+q_i。
- T_j=max(0,C_j-d_j)：任务延期；提前完成不计负延期，也不与其他任务延期抵消。

唯一优化目标：**min Σ_j T_j**。不把makespan、维护完成时间或加权指标替换进目标。

约束：

1. 每个任务恰好分配一次：Σ_i x_ji=1。
2. 加工不可抢占：占用所选机器的区间[s_j,C_j)。
3. 每台机器必须维护一次：[M_i,M_i+q_i)，且L_i<=M_i<=U_i-q_i。
4. 同机生产无重叠：若x_ji=x_ki=1，则C_j<=s_k或C_k<=s_j。
5. 加工与维护无重叠：若x_ji=1，则C_j<=M_i或M_i+q_i<=s_j。
6. T_j精确等于max(0,C_j-d_j)。报告仍应从最终调度独立重算，而非相信求解器输出的汇总数。

令U*=max_i U_i、P=Σ_j p_j，使用时域H=U*+P。先在各机器的L_i开始维护，全部维护在U*前完成，再将所有任务放到一台机器串行加工，可以构造H内的可行解。

H还保留最优目标值：取任意可行解，保持机器分配、每台机器上的生产/维护顺序和维护开始时刻M_i不变，将维护前后的生产任务分别逐项左移。因为所有任务r_j=0、没有跨机器工艺先后或换型约束，左移不会使任一任务完成更晚，也不破坏维护窗口。维护前任务原本就在M_i前结束，故其完成时刻不超过U*；维护后任务从M_i+q_i<=U_i<=U*开始连续加工，每台机器最后完成不超过U*加该机维护后加工总时长，进一步不超过H。因此任意可行解都可变为H内且ΣT_j不增加的解，限制到H不会损失最优值。这同时适用于维护时刻固定和维护时刻可调的模型。

该论证依赖当前首版假设；若引入释放时间、跨机器工艺先后、换型或其他资源约束，须重新论证。H只是变量上界，不是额外优化目标。

G2的CP-SAT表达沿用项目的optional interval/ExactlyOne/NoOverlap机制：每个任务—机器组合一个存在性为x_ji的加工区间，每台机器另有一个必需维护区间；按机器对所有存在的区间施加NoOverlap。维护不能做成可选区间后任由优化器删除。T_j使用精确max约束，并从最终计划独立重算总延期后核对原始求解目标，避免松弛延期变量被直接当作实际指标。

## 4. 固定维护与联合维护

固定方案预先给定f_i，要求L_i<=f_i且f_i+q_i<=U_i；增加M_i=f_i。其余生产分配和顺序仍可优化。f_i必须在比较前确定，不能看过联合方案后挑选更差的维护时机。

联合方案只移除M_i=f_i，保留同一维护次数、时长、窗口和所有生产约束。因此固定方案的可行域是联合方案的子集。**两者都求得OPTIMAL时，联合最优总延期不得大于固定最优总延期。** 若任一方仅为FEASIBLE或未知状态，限时得到的两个目标值可能逆序，不能据此断言模型违反理论关系，也不能将限时参考解说成最优。

比较时分别保存状态、实际重算总延期、求解器目标/界/耗时、同一时间预算、线程和种子。不同规模/维护条件的正式生成规则留待假设确认后冻结；本草案不凭空承诺算法性能或论文创新。

## 5. 可手算验证证人

### 单机器边界例

两任务p=(2,2)，d=(2,4)。唯一机器必须维护q=2，完整维护窗口[0,6)。固定f=0。

- 固定：维护0–2；任务A2–4、B4–6，延期2+2=4。换顺序为B2–4、A4–6，延期0+4=4；延迟开工不会改善。
- 联合：A0–2、B2–4、维护4–6，延期0。总延期非负，所以该联合方案已达到下界0。

### 两机器平行例

三任务p=(2,2,2)，d=(2,2,4)。两台机器都必须维护q=(2,2)，窗口均为[0,6)，固定f=(0,0)。

- 固定最早三个完工时刻为4、4、6，所有完工不早于对应可能的交期，最小总完工和为14，交期和为8，所以总延期下界6；A在机器0的2–4、C在机器0的4–6、B在机器1的2–4达到6。
- 联合：机器0排A0–2、C2–4、维护4–6；机器1排B0–2、维护2–4。三个延期均为0，达到非负下界。

这些是首版假设下的数学小例，先作为手工构造计划验证 G1，G2又用自动求解及独立枚举核对相同最优目标值。G1 同时拒绝漏维护、维护越窗、维护/加工重叠、漏任务、错误机器、时长不匹配及错误总延期等负例，见[G1验证](graduation_g1_validation.md)和[G2验证](graduation_g2_validation.md)。

## 6. 与现有代码的兼容方式（G1 已实现）

保留生产任务的统一ScheduleRecord/ScheduleResult：每任务映射为一个op_id=0的FJSP工件，所有机器选项时间均为p_j，继续运行原静态checker。

维护不是伪造的生产job，不能塞进原records后改checker放行。已实现的 MaintenanceScheduleResult 继承 ScheduleResult，增加独立 maintenance_records 和 total_tardiness；所有生产记录仍满足统一 ScheduleResult 契约，原检查器未修改。

新领域 checker 已联合检查原静态合法性、每机恰一次维护、机器与时长正确、完整维护区间在窗内、维护与生产互斥、固定模式满足f_i，以及从C_j和d_j独立重算Σmax(0,C_j-d_j)。makespan仍按生产records最大end定义；它可能小于维护结束时刻，例如两机器联合小例生产makespan=4而最后维护在6结束，这不影响总延期目标。度量函数本身不等于维护合法性验收，调用者必须检查领域 checker。

## 7. 实施进度与后续顺序

G0：首版设定和 G1 范围已获确认；完整任务书、最终算法要求及后续阶段放行仍待明确。

G1：已实现数据、总延期计算、独立维护记录与领域 checker，上述手工小例及负例通过73项专项测试。

G2：已实现小规模固定/联合CP-SAT参考模型及有界独立枚举，复核极小实例的可行性和总延期，严格区分OPTIMAL/FEASIBLE；具体证据见[G2验证](graduation_g2_validation.md)。

G3：冻结规模、维护窗口/强度、交期紧迫度、种子与预算，比较固定和联合方案；再根据任务书确定研究算法及论文/答辩材料。

本模型不实现AGV或RL，也不能作为大创生产—物流协同成果。大创依然需要按原计划书补齐运输、AGV、缓冲区、协同仿真、RL及成果要求。
