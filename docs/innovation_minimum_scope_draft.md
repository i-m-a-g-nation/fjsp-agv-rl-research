# 大创最小生产—物流协同范围：实施前草案

2026-10-25，多agent只读核对后的下一阶段建议。依据用户原申请书与当前代码，不是已批准模型、阶段放行、创新性证明或验收清单修改。本轮只实现毕设R2；AGENTS和冻结契约不变。

## 必须保留的问题

申请书要求工序、机器、运输任务、AGV位置/占用、缓冲区及动态扰动进入统一模型，使物流状态影响开工。维护调度、固定运输延迟、只有加工甘特图或PPO名称均不能抵扣这些能力。预期成果还含协同方法及发表/录用一篇学术论文。

当前可复用FJSP表达、机器资格、加工记录与检查、动态到达及历史冻结思路、事件重放、复现实验和工作流预算/审核。当前DynamicFJSPState、reschedule_from_state及ScheduleResult尚无工件位置、运输资源、缓冲占用与加工后阻塞；不能把它们当成已有物流仿真。

## 建议的最小闭环

- 保留非抢占FJSP；机器有位置，点间行驶时间显式给定。
- AGV单载荷，记录位置、空驶、装载、载货行驶和卸载；数量参数化，先验证1台，再验证2台分配竞争。
- 加工完成后关联下一工序和目标机器，显式释放运输；到达且满足机器/工序条件后才可开工。
- 每机器输入缓冲建议容量1；派发前预留容量、卸载转占用、开工释放。首版不设输出缓冲时，完成加工的工件留机至取走，机器期间阻塞。因此加工结束和资源释放时刻分开。
- 至少覆盖插单、AGV竞争和缓冲阻塞，检测无后续可行事件的死锁。加工、运输、缓冲预留/占用及阻塞轨迹分别留存。
- 新协同checker检查资源和工件守恒；既有加工checker继续保留。先用规则验证闭环，再接RL。

以上容量/阻塞/运输细节是设计建议，均须在实施前核对目标场景，不能从计划书宽泛描述中推定已经确认。

## 人需要理解并核对

1. 空驶和装卸是否计时间，首工序入料及末工序出库是否需要运输，同机连续工序如何处理。
2. 缓冲容量是否包含机床上的工件，预留何时占容量，加工后留机是否符合场景。
3. AGV是否同质、单载荷、运输不可中断；首版道路冲突、电量和充电的范围。
4. 机器分配何时锁定，同刻事件顺序，策略不得读取尚未发生的未来插单。
5. 完工是最后加工结束还是运抵出库；完工、延期、运输等待及重调度代价分别如何定义。

## 后续可核查证据

- 手算案例实际出现运输等待、机器闲置、缓冲满和加工后阻塞；故障窗口不代替物流。
- 注入重复运输、AGV重叠、工件瞬移、未到达先加工和超容量，检查器须拒绝。
- 多时刻重放冻结已完成/执行中的加工与运输，逐工件守恒核对位置。
- 相同模型、实例、扰动和预算下比较解耦/联合规则及基础RL；留失败行、独立测试和消融，不预断性能优势。
