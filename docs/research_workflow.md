# 科研辅助工作流运行与审核

工作流用于文献辅助和受控静态派工实验。当前开发阶段仍为 Phase 2A，不能实现或认证 AGV、运输、RL、GNN 或维护优化。要求清单描述长期课题目标，不会自动开放后续阶段权限。

## 三套要求配置

| track | 原始依据和目标 | 当前可以认证的内容 |
|---|---|---|
| foundation | AGENTS.md 的静态 FJSP 基础能力 | 本次静态调度合法性与有限算例性能观察 |
| innovation | 用户提供的大创申请书《基于深度强化学习的车间调度与车间物流协同框架设计与实现》中的研究内容、技术路线及预期成果 | 仅基础实验；物流、缓冲区、动态仿真和 RL 等要求仍未满足 |
| graduation | 用户提供的毕设截图：平行机生产与维护协同，考虑加工时间、交期、维护时长和允许维护时间窗，联合优化任务分配、顺序和维护时机，最小化总延期，并比较固定维护方案 | 仅基础实验；完整任务书及机器假设待人工核对，专用模型与实验尚未实现 |

大创原文提出兼顾完工、延期、等待、重调度等指标，未固定具体组合；必须由人审核后才能锁定。毕设截图列举智能优化、强化学习等算法，不据此要求全部实现。两个课题不能以同一静态派工结果互相替代。

权威要求在 `src/ai_workflow/contracts.py` 中版本化，使用冻结对象和 SHA-256 标识。调用者传入的报告、自由目标或 RAG 文本不能覆盖要求。改变要求需经人工核对原始材料并修改版本；修改要求本身不算实现。

## 安装与运行

使用项目 `.conda-env` 或 `FJSP_CONDA_ENV` 指定的专用环境。先执行 `python -c "import sys; print(sys.executable)"` 核对路径，再安装 `python -m pip install -e ".[dev,research]"`。勿使用 base。

```powershell
python experiments/exp_018_ai_rag_workflow.py --track foundation
python experiments/exp_018_ai_rag_workflow.py --track innovation
python experiments/exp_018_ai_rag_workflow.py --track graduation
```

入口现在会创建持久会话，先停在范围审核，返回 `3`；不再一次执行到底。原有 `build_research_workflow()` 低层接口保留，用于测试和嵌入，但只有会话入口提供完整的外层进程监督和累计执行预算。

## 持久审核与恢复

建议明确指定一个尚未使用的会话目录：

```powershell
python experiments/exp_018_ai_rag_workflow.py --track graduation --session-dir .\experiments\ai_memory\graduation\my-run --max-active-seconds 120 --max-provider-calls 8 --max-output-token-budget 16384
python experiments/exp_018_ai_rag_workflow.py --track graduation --session-dir .\experiments\ai_memory\graduation\my-run --status
```

三道审核按顺序执行：

| 阶段 | 人应核对的内容 | 审核后允许的动作 |
|---|---|---|
| scope | 原始课题要求、当前 Phase 2A 范围、论文标识、算例指纹、运行配置和预算 | 建立索引、读取文献、在已批准预算内调用模型 |
| evidence | 文献原文与提取结果、公式依据、模型假设、缺失项 | 生成并运行基础派工候选实验 |
| conclusion | 实际数据、失败和降级、合法性、性能观察、未满足的研究要求 | 结束本次审核并保存结论 |

每次暂停会写入 `review-request.json` 和空白的 `decision-template.json`。审核人阅读材料后，复制模板为独立的决定文件，填写 `decision` 为 `approve` 或 `reject`，填写真实 `reviewer` 和说明，保留本轮 `stage`、`artifact_hash` 的完整原值。不要把 AI 自动生成批准文件当作人工确认。

```powershell
python experiments/exp_018_ai_rag_workflow.py --track graduation --session-dir .\experiments\ai_memory\graduation\my-run --decision-file .\decision-scope.json
```

随后会停在下一道审核，必须使用下一轮模板及哈希。`reject` 会终止会话。审批只允许本阶段基础实验继续，不把未核实公式变成已核实，也不把大创或毕设未达成状态改成完成。本地审核记录不是身份认证或不可篡改电子签名。

SQLite 保存真实检查点和决定，`status.json` 仅作展示；恢复前必须核对真实待审节点。输入、课题、代码、依赖版本、工作区、算例内容和预算均被绑定。显式传入与原会话冲突的参数（包括 `--no-network-fetch`）会被拒绝；需要改动时创建新会话，不会悄悄忽略参数。代码更新后的旧会话也不能继续运行。

正常暂停可以跨进程恢复，不重复已完成的提取或实验。失败、拒绝、预算耗尽以及监督进程异常中断后的会话不自动重试；保留证据并创建新会话。RAG 快照与检查点关联并校验哈希，缺失向量不会在审核前隐式重建。不要复用只有旧索引而没有会话元数据的目录。

默认离线，无模型 API 调用、无论文网络抓取，也不自动读取 `.env`。`--mode live` 才读取 `.env` 并要求 API key，且要求正文候选；`--allow-network-fetch` 才允许论文抓取。不要把 `.env`、认证状态或完整密钥加入版本控制。

离线提取始终标为 `unverified_template`，不填写原文没有的公式、奖励或网络结构。`full_text` 只是内容结构的候选分类，不表示公式或结论被核实。模型提取仍标记为未审核，需要逐项核对原文。

下载内容的缓存另存获取类型、论文标识和文本哈希；重读时核对一致性，避免真实 PDF 正文因措辞不同降为摘要，也避免修改后的缓存继续继承原获取类型。这份来源记录不代替公式审查。

新缓存另绑定获取请求：有 DOI/arXiv 时绑定其组合；仅有标题时绑定标题及原始输入文本。文件名相同不能证明来自同一论文。没有来源记录的旧缓存、没有标识或请求绑定的旧缓存不再自动替换目标文献，须重新获取或显式选择本地原文。版本 1 中带有匹配 DOI/arXiv 且文本哈希正确的记录仍可使用；缺少关联 PDF 字节哈希时不继承邻近 PDF 的页码。新缓存只有对应 PDF 哈希一致时才恢复物理页码。

## 逐项原文证据

模型提取的每项问题定义、数学模型和 RL 陈述通过 `claim_evidence` 引用目标文献。引用包含允许的字段路径、列表项下标（从 0 开始；标量用 `null`）、至少 12 个字符的原文，以及可选的 `source_start`。单独的 `source_quotes` 列表不能替代逐项引用，其他 RAG 文献中的引文也不能替代目标原文。

确定性检查器重新生成 `evidence_audit`，覆盖模型自报的审核状态。在线检查只使用本次提供给模型的前 28000 个目标文本字符。重复片段必须用准确字符偏移消歧；缺失、找不到、错误下标和越过可见文本的引用会明确列出。

| 逐项状态 | 含义 | 人工下一步 |
|---|---|---|
| `located_unreviewed` | 引文与目标文本匹配，位置可定位 | 判断引文是否真正支持该陈述、公式是否正确 |
| `missing` | 陈述没有对应引用 | 补读原文，补充依据或删除陈述 |
| `invalid` | 引文不存在、太短、偏移错误或越过可见文本 | 修正引用并重新提取 |
| `ambiguous` | 原文有多处相同片段，未提供有效偏移 | 指定确切原文位置 |

字符区间按 Python Unicode 字符计数，起点从 0 开始，终点不包含；行号从 1 开始，针对保存的解析文本，而非 PDF 印刷行号。PDF 页码指文件内从 1 开始的物理页，包含空白页，不等于论文印刷页码。只有重新解析的 PDF 正文能与目标文本唯一对应时才显示页码；缓存前缀、不同版本、无法解析的扫描件等只显示有依据的文本位置和提示。文本首尾空白裁剪按下载器实际转换处理，不猜测内部排版或 OCR。

审核请求和最终报告包含逐项状态、原文片段、位置及文本 SHA-256。原始文件和关联 PDF 另存字节哈希；持久会话恢复前检查文件是否改变或丢失。缓存发生变化时也必须建立新会话。保存的检查点文本是复核坐标的依据。

即使 `all_claims_located=true`，`evidence_status` 仍为 `unverified`。文字匹配不能证明语义支持、公式正确或实验结论成立，人工批准也不会自动提升这些状态。报告中的“项目接口适配建议”是应用建议，需要单独判断，不能当作论文原文结论。

模型服务异常默认失败。显式 `--allow-fallback` 可允许分析/生成阶段退回演示模板，但结果标为 `DEGRADED`，记录阶段及错误类型。远程向量服务失败直接报错，避免混用向量空间。

## 结果含义

报告和相邻 JSON 分别记录要求版本、执行模式、文献证据、调度合法性、性能观察、未满足要求和人工审核提示；JSON 另记录输入文件哈希、Python 和依赖版本以及固定 seed 42。

- `DEMO_ONLY`：离线流程演示，不是论文复现或课题达标。
- `DEGRADED`：模型调用失败后显式降级，不得作为正式研究结果。
- `FAILED`：执行、数据或合法性失败。
- `REVIEW_REQUIRED`：在线候选实验已运行，证据和课题结论仍须审核。

退出码：`3` 表示等待人工审核；`0` 仅表示 foundation 演示及三道审核完成；`1` 表示失败、拒绝、降级或预算耗尽；`2` 表示三道审核结束但研究目标仍未验收（也用于 argparse 参数错误，应结合输出区分）。innovation 和 graduation 当前完整审核后仍返回 `2`，即使静态调度合法。

会话的 `COMPLETED` 只表示本次运行与审核结束；科研报告仍可能是 `DEMO_ONLY` 或 `REVIEW_REQUIRED`，并继续列出课题缺口。`BUDGET_EXHAUSTED` 是独立终止状态，不能触发离线降级以绕过额度。

默认产物放入 `experiments/ai_memory/<track>/<UTC run id>/`，避免课题混写和旧结果覆盖。可用 `--output-report`、`--rag-index-dir` 指向自定义目录。未审核的自动记录不会作为可信记忆检索；不同课题的已审核记忆也分开检索。RAG 不是权威规则执行器。

自动报告带有来源标记；无论经目录扫描还是 `extra_paths` 导入，都保留未审核状态。已知旧版报告标题和 `ai_memory` 路径也会被隔离，不能通过换一条导入路径转成可信文献。

## 执行边界

生成规则必须是无导入的纯候选选择函数，实例只读，返回值必须来自本轮候选集合。禁止属性修改、内部属性访问、方法调用、while、类及顶层可执行语句。规则在独立 Python 进程中执行，默认墙钟上限 10 秒、进程内存上限 2048 MiB；Windows 使用 Job Object，POSIX 使用 RLIMIT_AS，无法设置限制即失败。父进程使用未修改的实例重新检查每一条返回调度。

每个模型请求默认超时 30 秒、最多输出 4096 tokens、不自动重试；工作流最多允许 3 轮生成。持久会话另有默认累计执行时间 120 秒、供应商调用 8 次、输出 token 预占 16384 的上限。模型和远程向量调用在发送前提交预占，失败或中断也不退款；SDK 若配置重试，则按最大尝试数预占。输出预占不是实际生成量，也不包括输入或 embedding token，因此不是货币费用封顶。

执行时间累计覆盖受监督进程中的论文解析、RAG、网络和模型调用、调度实验及恢复；人工等待和只读状态查询不计入。父进程的参数、配置和文件指纹核对属于启动校验。每段执行先持久预占剩余时间，正常退出再按实际时长结算；监督进程崩溃时，未结算额度保留占用，不能靠重启重置。`active_seconds` 是已结算时长，`active_seconds_reserved` 是未结算预占，`active_seconds_charged` 是两者之和。

Windows 用 Job Object 拥有整个进程树；Linux 用独立进程组、父进程死亡信号和只持有生命期管道读端的看门狗，监督进程消失时终止执行树。其他平台目前拒绝启动持久执行。当前不提供任意恶意 Python 的 OS 安全隔离，外来代码仍需审核。Linux 的真实进程死亡集成用例由 Linux CI 执行；本地 Windows 结果不能当作 Linux 验证。

## 人工审核点与后续工作

人审核原始目标、模型假设、原文公式、正式实验协议及最终结论；固定规则负责范围、资源、调度和缺失数据检查。现在不增加多 AI 协作。需要先补齐对应模型，再扩展验收后端，不能通过把能力名称写入模型输出宣称完成。

下一批独立工作可增加正式研究协议与专用课题模型。真实在线供应商及机构认证仍需在明确预算内单独验证。archify 适合展示要求—代码—实验对应关系，不参与最终合法性判定。
