# 术语表

按主题分组。每条先给通俗解释，必要时再给项目里的具体用法。原理见 [模型与算法原理](methods.md)。

## 调度问题

| 术语 | 解释 |
|---|---|
| 调度（scheduling） | 决定每项工作由哪个资源、在什么时间做 |
| 工件（job） | 要加工的一个产品或零件 |
| 工序（operation） | 工件加工过程中的一步；同一工件的工序要按顺序做 |
| 作业车间（JSP, job shop） | 每道工序只能在指定的一台机器上做 |
| 柔性作业车间（FJSP） | 每道工序可以在若干台机器中任选一台，不同机器加工时间可能不同 |
| FJSPT | 带运输（transport）的 FJSP，工件在机器间移动需要小车 |
| 平行机（parallel machines） | 多台功能相同的机器，任一工件可以放到任一台上；本项目毕设用的是**同质**平行机（加工时间与机器无关） |
| 可选机器 | 一道工序允许使用的机器集合 |
| 加工时间（p） | 工序在某台机器上需要的时间 |
| 交期（due date, d） | 工件应完成的时刻 |
| 完工时刻（C） | 工件实际完成的时刻 |
| 延期（tardiness, T） | max(0, C − d)：迟交多少；提前完成记 0 |
| 总延期 ΣT | 所有工件延期之和；毕设的优化目标 |
| makespan（C_max） | 全部工件做完的时刻；Phase 1 与大创的优化目标 |
| 不可抢占 | 一道工序开始后不能中途停下换别的 |
| 非延迟（non-delay） | 只要有机器空着、有活可做，就不让机器空等 |
| 半主动调度 / 左移 | 在不改变先后顺序的前提下，每件事都尽早开始 |
| 合法（可行）调度 | 满足全部约束的调度 |
| NP 难 | 一类被认为不存在多项式时间精确算法的问题；规模一大就无法求最优 |
| 算例（instance） | 一组具体的输入数据（工件、机器、时间……） |
| 基准算例（benchmark） | 学术界公开、反复使用的算例，便于互相比较，如 FJSPLib、Brandimarte（mk01–mk10） |
| BKS / 已知最好值 | 文献中报告过的最好解的目标值 |

## 维护（毕设）

| 术语 | 解释 |
|---|---|
| 预防性维护 | 机器按计划停机保养，期间不能加工 |
| 维护窗口 [L, U) | 允许做维护的时间段；维护必须完整落在窗口内 |
| 周期性维护 / 多窗口 | 一台机器有多个依次排列的窗口，每个窗口都要维护一次 |
| 固定维护（fixed） | 维护开始时刻事先定好（本项目取窗口中点），只优化生产 |
| 联合维护 / 协同优化（joint） | 维护开始时刻也由算法决定，与生产一起优化 |
| α、β、τ | 算例参数：α 维护时长、β 窗口宽松度、τ 交期松紧（越小越紧），都按机器平均负荷的百分比给出 |

## 物流（大创）

| 术语 | 解释 |
|---|---|
| AGV | 自动导引小车，负责在机器之间搬运工件 |
| 单载 | 一辆车一次只拉一个工件 |
| 空驶 / 载货行驶 | 车去取货的路程 / 拉着工件送货的路程 |
| L/U 站 | 装卸站（load/unload），工件进出车间的地方 |
| 布局（layout）/ 行驶时间矩阵 | 各地点之间的行驶时间表 |
| 输入缓冲（B） | 机器前面暂放待加工工件的位置数；B = ∞ 表示不限，B = 0 表示没有缓冲 |
| 工位容量 | 一台机器同时能容纳的工件数 = 1（机器本身）+ B |
| 阻塞（blocking） | 工件加工完后留在机器上，直到被车取走，机器才能做下一个 |
| 死锁（deadlock） | 互相等待、谁都动不了的状态，例如两台满载机器上的工件都要去对方那里 |
| 前瞻式死锁规避 | 执行一个决策前，先在副本上推演到结束；能完成才执行 |
| 联合 vs 解耦 | 同时决定生产和运输 vs 先排生产、再派车 |
| 事件仿真器 | 按时间顺序推进"开工、完工、取货、送达"等事件的程序；每到可以决策的时刻就让规则或策略选一个动作 |

## 求解方法

| 术语 | 解释 |
|---|---|
| 派工规则（dispatching rule） | 用一个简单的优先级逐个挑工作的方法，速度极快 |
| FIFO / SPT / EAM / EFT / MWKR / MOPNR | 先到先做 / 最短加工时间优先 / 最早可用机器 / 最早完工 / 剩余工作量最多优先 / 剩余工序数最多优先 |
| EDD | 最早交期优先 |
| MDD | 修正交期 max(d, t + p) 最小者优先 |
| ATC | 表观延期代价规则，综合考虑加工时间和离交期的松弛；参数 k 控制看多远 |
| 精确方法 | 能证明最优的方法，代价是规模受限 |
| CP-SAT | Google OR-Tools 里的约束规划求解器；本项目所有精确模型都用它 |
| 可选区间 / NoOverlap | CP-SAT 的建模部件：一段可能存在也可能不存在的时间区间 / 一组区间互不重叠的约束 |
| OPTIMAL / FEASIBLE | 求解器状态：已证明最优 / 只找到限时内的可行解（不能称最优） |
| 下界 | 最优值不可能低于的数；与上界之间的距离说明离最优还有多远 |
| 枚举（enumeration） | 列举全部方案求最优，只适用于极小规模，用来核对 CP-SAT |
| 元启发式 / 智能优化算法 | 在解空间里迭代改进的通用搜索框架，如 GA、SA |
| 编码 / 解码 | 用一个排列等简单结构表示解 / 把这个结构翻译成具体调度 |
| GA（遗传算法） | 模拟"选择—交叉—变异"的种群搜索 |
| SA（模拟退火） | 每次小改动，变差也以一定概率接受，概率随"温度"下降而变小 |
| IGA（改进遗传算法） | 本项目在 GA 上加了启发式初始解和局部搜索 |
| 局部搜索 | 在当前解附近做小改动，只保留变好的 |
| 评估次数 / 解码次数 | 搜索算法算了多少个解的目标值，用来统一不同算法的计算量 |
| 热启动（warm start） | 用别的方法给出的好解作为搜索的起点 |

## 强化学习

| 术语 | 解释 |
|---|---|
| 强化学习（RL） | 让程序反复尝试，根据结果好坏调整自己的选择方式 |
| MDP（马尔可夫决策过程） | 强化学习的问题形式：状态 → 选动作 → 新状态 → ……，结束时得到回报 |
| 构造式策略 | 每一步往调度里加一个决定，一步步把整个调度"搭"出来 |
| 策略（policy） | 给定状态，给出各个动作的选择概率的函数；本项目用神经网络表示 |
| 候选动作 / 动作掩码 | 当前能选的动作 / 把不合法（或不安全）的动作屏蔽掉，使其概率为 0 |
| 特征 | 描述一个候选动作的数字，如加工时间、预计延期；网络只看这些数字 |
| 回报（reward） | 对结果的评价；本项目只在结束时给出：−总延期或 −makespan |
| 模仿学习 / 行为克隆（BC） | 让网络学着重复"老师"（这里是 IGA 或最好的规则）的选择 |
| 教师数据 | 老师在训练算例上的示范决策序列 |
| REINFORCE | 最基本的策略梯度算法：结果好的选择，概率调高；结果差的，调低 |
| 基线（baseline） | 用来比较"好还是差"的参照值；本项目取同一算例多次采样的平均（POMO 式共享基线） |
| PPO | 一种更复杂的策略梯度算法；本项目**没有**使用 |
| 注意力（attention）/ Transformer | 一种神经网络结构，让每个候选在打分时参考其他所有候选 |
| MLP（多层感知机） | 最简单的全连接神经网络；大创 L2 策略用的是 20 → 32 → 1 的两层 MLP |
| 贪心 / 采样 | 每步选概率最高的动作 / 按概率随机选；采样 K 次取最好可以换来更好的解 |
| 检查点（checkpoint） | 训练过程中保存的一版网络参数 |
| 训练集 / 验证集 / 测试集 | 用来训练 / 用来挑选检查点 / 最后只用一次、报告正式结果的算例集合，三者互不重叠 |
| 训练种子 | 控制训练随机性的数字；换种子重训可以看结果是否稳定 |
| GPU / CPU 推理 | 用显卡 / 处理器运行网络；单个算例时 CPU 往往更快（GPU 有固定开销） |
| bf16 | 一种半精度数值格式，用来在 GPU 上加速并省显存 |

## 实验与统计

| 术语 | 解释 |
|---|---|
| 时间预算 | 允许一个方法在一个算例上用的时间 |
| 质量—时间曲线（anytime） | 在各个时间预算下，方法已得到的最好解的质量 |
| best-known | 某算例上所有方法找到的最好目标值 |
| gap | (T − best-known) / max(1, best-known)，比已知最好解差多少 |
| 覆盖率 / 无解 | 在给定时间内有解的算例比例 / 时间到了还没给出解 |
| 预先登记的假设（H1、H2……） | 实验前写进协议、要检验的具体命题 |
| 探索性分析 | 看到结果后才补做的分析，只能作为线索，不能当作已证实的结论 |
| Wilcoxon 符号秩检验 | 比较配对数据的非参数检验，看一方是否系统性地更小 |
| 单侧检验 / p 值 | 只检验"更好"这一个方向 / 在"其实没差别"时看到这么极端结果的概率；小于 0.05 视为显著 |
| Holm 校正 | 同时做多个检验时对 p 值的修正，防止多做几次就"碰巧显著" |
| 基础数据 / 簇 | 多个算例共用的那部分随机数据（G4/G5 的加工时间与交期分位数，L2 的基准算例）；共用同一份的算例算一簇，彼此不独立 |
| 符号翻转检验 | 按簇的精确检验：每簇的平均差值算一票，枚举所有正负号组合；k 个簇时 p 最小只能到 2^−k |
| 胜 / 平 / 负 | 一种方法相对另一种方法更好 / 相同 / 更差的算例数 |
| 计时干扰 | 运行时机器上的其他任务让测得的时间变慢 |

## 工程与证据

| 术语 | 解释 |
|---|---|
| 检查器（feasibility checker） | 独立核对调度是否满足全部约束、重算目标值的程序；不通过就报错 |
| ScheduleRecord / ScheduleResult | 统一的调度记录（工件、工序、机器、开始、结束、时长）/ 一组记录加目标值，所有算法都返回它 |
| 不可变（immutable） | 数据创建后不能被修改，避免算法偷偷改算例 |
| 协议（protocol） | 实验前写好的设计与判定规则，见 `docs/protocols/` |
| manifest.json | 每个结果目录里的"出处证明"：git 提交号、是否有未提交改动（`git_dirty`）、全部源码的 SHA-256 哈希、包版本 |
| git_dirty | 运行时代码是否有未提交的改动；正式结果必须为 false |
| SHA-256 哈希 | 文件的"指纹"，内容变一个字节哈希就不同，用来核对数据和代码没被改过 |
| findings.md | 每批实验的结论说明 |
| 归档（archive / results） | 已经定稿、不再修改的结果目录 |
| 回归测试 | 防止以后改代码把原来正确的行为改坏的测试 |
| Conda 环境 | 独立的 Python 环境；本项目用专用环境 `.conda-env`，PyTorch 部分用本机已有的环境 |
