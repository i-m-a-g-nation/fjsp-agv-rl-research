# 大创 L1：带 AGV 运输与有限缓冲的柔性作业车间模型

范围：2026-11-01 用户批准的大创第一阶段（L1），静态、确定性，**不含强化学习**。
建模依据见[建模决策建议](../plans/innovation_modeling_decisions.md)。本文是 `src/fjsp_lab/logistics/` 和检查器的实现规格。

## 1. 对象与数据

- **生产部分**：一个普通 FJSP 实例（`fjsp.FJSPInstance`），工件 j 的工序 o 有可选机器及加工时间。
- **地点**：机器 0..m−1，L/U 站编号为 m。
- **行驶时间矩阵** τ[a][b]（a、b ∈ 0..m）：非负整数，对角线为 0，可以不对称。
  空驶和载货行驶使用同一矩阵。
- **装卸时间** h ≥ 0：加在每次载货行驶上，默认 0，即装卸已并入 τ（Bilge & Ulusoy 的约定）。
- **车辆**：V 台同质、单载 AGV，0 时刻都停在 L/U 站。
- **输入缓冲容量** B_i：每台机器一个，取值为非负整数或"无限"。
- **送回 L/U 开关** R：开时，末工序完成后要运回 L/U；关时，末工序结束即完工。
- **阻塞开关**：开（默认，本课题的研究设定）时，加工完的工件留在机器上直到被取走；
  关（FJSPT 基准算例的约定）时，工件加工完立即进入容量无限的输出缓冲，不占机器，也不占工位。

## 2. 访问、运输与阻塞

- **访问**：工件在同一台机器上连续加工的若干道工序合并为一次访问。
  只有在访问之间才需要运输；同机连续工序不需要运输。
- **工件 j 需要的运输**：
  - 入站运输：L/U → 第一次访问；
  - 中间运输：每两次相邻访问之间各一次；
  - 出站运输：R 打开时，最后一次访问 → L/U。

  运输以"它送往的工序号"标识，记为 leg；出站运输的 leg 等于工序数。
- **运输记录**有六个时刻量与资源：
  - 车辆 v；
  - 起点 a、终点 b；
  - 派车时刻 d：车辆从上一个位置空驶出发；
  - 取货时刻 s；
  - 送达时刻 e。
- **合法性条件**：
  1. e = s + τ[a][b] + h；
  2. d + τ[车辆上一位置][a] ≤ s；
  3. 同一车辆的运输按时间先后串联：下一次的 d ≥ 上一次的 e；车辆的第一次运输从 L/U 出发，且 d ≥ 0。
- **取货与开工的先后**：
  - 取货不早于起点那次访问最后一道工序的结束时刻；从 L/U 取货不早于 0；
  - 访问的第一道工序开工不早于入站运输的送达时刻。
- **阻塞**（阻塞开关打开时）：工件在出站运输取货前一直留在机器上。
  访问对机器的占用区间是 [第一道工序开工, 释放)，释放时刻 = 出站运输的取货时刻；
  没有出站运输时（R 关闭的最后一次访问），释放时刻 = 最后一道工序结束。
  同一台机器上，不同访问的占用区间不得重叠。这比"加工不重叠"更严格。
  阻塞关闭时，机器只在加工期间被占用；工位在访问最后一道工序结束时释放。
- **工位容量**：机器 i 的工位共有 1 + B_i 个位置，即机器本身 1 个，加上输入缓冲 B_i 个。
  一次访问从入站运输的**派车时刻**（预留）起，到释放时刻止占用一个位置。
  阻塞关闭时，释放时刻为访问最后一道工序的结束时刻。
  任一时刻占用数不得超过 1 + B_i；B_i 为无限时不检查。L/U 站容量无限。

## 3. 目标

工件完工时刻：R 打开时为出站运输的送达时刻，R 关闭时为最后一道工序的结束时刻。
目标是 makespan = 所有工件完工时刻的最大值。

## 4. 检查器（`logistics.feasibility`）

逐条检查以下内容，不修复调度：

1. 生产部分交给**不改动的** Phase 1 静态检查器，覆盖每道工序恰好一次、工艺顺序、可选机器、时长、加工不重叠；
2. 每个工件需要的运输恰好各一次，没有多余的运输，起点和终点与访问一致；
3. 运输时长、取货不早于工序结束、开工不早于送达；
4. 车辆编号合法；同一车辆的运输按时间串联，空驶时间足够；
5. 阻塞打开时，访问的机器占用区间不重叠；
6. 工位占用数不超过 1 + B_i；
7. 报告的 makespan 等于独立重算的值；所有时刻都必须是整数。

## 5. 与基准算例的对应（已核对）

- **数据来源**：
  - Deroussi & Norre (2010) 的 10 个算例，以及 Berterottière 等 (2024) 的参考解，
    取自 github.com/lucasberter/FJSPT（提交 c9b85d8）；
  - 行驶时间矩阵取自 FAST Manufacturing 项目公开的算例说明 PDF 表 5（Deroussi & Norre 的 8 机布局，第一行为 L/U）。
    注意：该仓库里的 `layout8.txt` **不是**这组算例的矩阵。
  - 这些数据没有开源许可证，只放在本地被 git 忽略的 `instances/external/FJSPT/`，不提交。
- **基准约定**：R 关闭、B 无限、h = 0、阻塞关闭；L/U 为矩阵第一行，即 `parse_fjspt` 的默认值。
- **核对结果**（回归测试 `test_published_reference_solutions_replay_to_their_reported_makespans`，本地有数据时运行）：
  - 按这些约定，用 `logistics.sequences` 把 10 个参考解重放一遍，makespan 全部与作者报告值一致，并都通过检查器；
  - 如果改为阻塞开启，或把 L/U 放在最后一个地点，则不一致或出现矛盾。

## 6. 已知简化

- 不考虑路径冲突、拥堵、充电、多载 AGV，也不考虑动态事件（见 AGENTS 与建模决策）。
- 仿真器中，输入缓冲按先到先加工处理；机器分配在派车时锁定。
- 有限缓冲加阻塞可能产生死锁。仿真器检测到死锁时报告失败，不返回调度。
- 模型允许两台车在同一时刻分别取走两个工件并互换机器：取货时机器即空出，派车即预留，时刻上首尾相接即可。
  仿真器每次只做一个决策，做不到这种同时互换，所以规则遇到的部分"死锁"在模型里其实可解，CP-SAT 能找到这类调度。
- 死锁规避（`simulator.avoid_deadlock`，规则可选 `avoid_deadlock=True`）：规则选中一个动作后，先在仿真器副本上执行它，
  再用保守策略推演到结束（先把已进车间的工件推完，车间清空后才从 L/U 放行下一个）；推演成功才执行这个动作，
  否则换规则的下一个偏好，都不安全就等待。推演成功即证明此后能完成；推演失败不代表一定死锁，所以这种规避是保守的。
  不会死锁时，结果与原规则完全相同。
- 解耦基线（`logistics.decoupled`）：第一阶段只排机器（D0 不计运输；D1 把载货行驶时间当作工序间隔，假设车辆随时可用），
  第二阶段固定机器方案，用 CP-SAT 只优化车辆与时间。机器方案无法执行时如实报告，不做修补。
- `logistics.sequences` 按给定的机器顺序和车辆顺序生成最早时间表，不处理缓冲容量；缓冲是否超限交给检查器判断。
