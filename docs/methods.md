## 1. 调度问题的共同骨架

所有调度问题都由三样东西组成：

- **要做的事**：工件（job）和它的工序（operation），每道工序需要一段加工时间；
- **能用的资源**：机器、AGV 小车、缓冲区的位置；
- **评价好坏的目标**：例如全部做完的时间最早（makespan），或者迟交的总时间最少（总延期）。

一个**调度**就是给每道工序定下"在哪台机器、从几点开始、到几点结束"。它必须满足**约束**（同一台机器同时只能做一件事、
工序按工艺顺序做……）才算**合法**。

这类问题绝大多数是 **NP 难**的：可能的排法随规模爆炸式增长，规模一大就无法枚举全部方案找最优。所以研究里通常同时用几类方法：

| 方法类型 | 思路 | 优点 | 缺点 | 本项目中的例子 |
|---|---|---|---|---|
| **派工规则** | 每次按一个简单的优先级挑下一件事（如交期最早的先做） | 极快（毫秒级） | 质量一般 | FIFO、SPT、EDD、MDD、ATC、EFT |
| **精确求解器** | 把问题写成数学模型，交给求解器系统搜索，可以证明最优 | 能给出最优解或下界 | 规模稍大就算不动 | CP-SAT、暴力枚举 |
| **元启发式（智能优化）** | 在"排列"的空间里反复改进：交叉变异、退火接受差解 | 时间越长越好 | 需要多次评估，大规模时慢 | GA、SA、IGA |
| **学习型策略（强化学习）** | 训练一个神经网络，每一步给候选动作打分，一次构造出整个调度 | 训练后出解很快、可推广 | 需要训练；结果不保证最优 | 注意力策略、L2 打分策略 |

### 本项目的硬性约定：检查器

不论哪种方法，给出的调度都要交给一个**独立编写的检查器**逐条核对约束，并且**重新计算目标值**，和算法自己报告的值比较。
任何一条不满足都直接抛出异常。这样能防止"算法有 bug 但看起来结果很好"的情况。
检查器只检查、从不修改调度；也不允许为了让结果通过而放松检查。

## 2. 底座：静态柔性作业车间（Phase 1）

**问题**：有若干工件，每个工件有一串工序，必须按顺序加工；每道工序可以在几台**可选机器**中的任意一台上做，
不同机器上的加工时间可能不同。"柔性"指的就是机器可选。目标是 makespan 最小。

数据格式 `jobs[工件][工序] = [(机器, 加工时间), ...]`，例如：

```text
工件 0：工序 0 可在 M0 做 3 分钟或 M1 做 5 分钟；工序 1 可在 M1 做 4 分钟或 M2 做 6 分钟
工件 1：工序 0 可在 M0 做 2 分钟或 M2 做 4 分钟；工序 1 只能在 M1 做 3 分钟
```

**7 条派工规则**（`fjsp.rules`）：每次只看各工件"下一道还没排的工序"，按规则挑一个，再挑机器。

| 规则 | 挑哪道工序 |
|---|---|
| FIFO | 先到先做 |
| SPT | 加工时间最短的先做 |
| EAM | 可用得最早的机器先接活 |
| EFT | 能最早完工的"工序—机器"组合先做 |
| MWKR | 剩余工作量最多的工件先做 |
| MOPNR | 剩余工序数最多的工件先做 |
| Random | 随机（固定种子，可复现） |

**解码**（`fjsp.decoding`）：规则只决定"先后顺序和机器"，具体时刻由解码器算出：每道工序在机器空闲且前一道工序完成后**尽早**开始
（半主动调度，不会无故空等）。

**CP-SAT 精确模型**（`fjsp.cpsat`）：Google OR-Tools 的约束规划求解器。建模方式：

- 每个"工序—可选机器"组合建一个**可选区间**（存在与否由求解器决定）；
- 每道工序恰好有一个区间存在（恰好选一台机器）；
- 同一工件相邻工序先后相接；同一台机器上的区间互不重叠（NoOverlap）；
- 目标是最小化 makespan，并设时间上限。

求解器返回 `OPTIMAL` 才能说"最优"；只返回 `FEASIBLE` 时，它是"限时内找到的可行解"，不能称最优。

**检查器**（`fjsp.feasibility`）核对 7 条：每道工序恰好加工一次；工艺顺序；同机不重叠；机器属于可选集合；
时长 = 结束 − 开始；时长与算例一致；makespan 等于最晚结束时刻。

结果：30 个 FJSPLib 基准算例加 1 个玩具算例，8 种方法共 248 个调度全部通过检查；CP-SAT 10 秒内 15 个证得最优，18 个达到公开的已知最好值。

## 3. 动态重调度（Phase 2A）

真实车间会出意外。Phase 2A 支持三类事件：

- **机器故障与维修**：某台机器在一段时间内不能用；
- **新工件到达**：中途插入新的工件；
- **加工时间变化**：某道工序实际需要更长或更短时间。

处理办法（`dynamic.reschedule`）：在事件发生的时刻 t，

1. **冻结**已经完成和正在加工的工序（`snapshot`）：它们已经发生，不能改；
2. 构造事件后的**状态**（`state`）：哪些机器何时可用、新工件何时到达；
3. 对**剩余**工序用派工规则重新排；
4. 结果先过静态检查器，再过**动态检查器**：冻结的记录没被改动、新工件不早于到达时刻开工、故障期间机器没被使用。

这是一个"最小基线"，目的在于搭好动态问题的底座；固定协议下 243 次重调度全部通过检查。

**注意：毕设和大创目前都没有用到这个模块。** 两个课题研究的都是静态问题（所有信息在开始时已知、过程中没有意外）。
大创申请书要求的"动态扰动"尚未开展；将来做时更适合在大创的事件仿真器里加入新事件，而不是直接套用本模块（见[项目全景](overview.md)第 3 节）。

## 4. 毕设：带维护窗口的平行机调度

### 4.1 问题

- m 台**相同**的机器（平行机），n 个工件，每个工件只有一道工序，加工时间 p_j，交期 d_j，0 时刻全部到达；
- 每台机器有一个或多个**维护窗口** [L, U)：在每个窗口里必须完整地做一次时长为 q 的维护，维护期间不能加工，空闲的机器也要维护；
- 目标：**最小化总延期** Σ max(0, C_j − d_j)，C_j 是完工时刻。提前完工不算负数，不能抵消别人的延期。

**两种维护方式**：

- **固定维护**：维护开始时刻事先定死（取窗口中点），算法只能决定工件分配和顺序；
- **联合（协同）维护**：维护开始时刻也由算法在窗口内决定。

固定方式的每一个可行方案，联合方式也都能做到（固定 ⊆ 联合），所以在都求得最优时，联合的总延期一定不会更差。
研究要回答的是"好多少、什么条件下好得多"。

**小例子**（单机）：两个工件加工时间都是 2，交期分别是 2 和 4；维护时长 2，窗口 [0, 6)。

- 固定在 0 时刻维护：维护 0–2，工件 A 2–4、B 4–6，延期 2 + 2 = 4；
- 联合：A 0–2、B 2–4，维护放到 4–6，延期 0。

**算例生成**（`maintenance.generator`）：按种子确定性生成，可以控制规模（n、m）、维护时长 α、窗口宽松度 β、交期松紧 τ、
窗口个数的分布（每台机器 2 个，或 1–3 个混合）。训练、验证、测试用的种子区间互不重叠，测试集在训练结束后只用一次。

### 4.2 派工规则 EDD / MDD / ATC

每当有机器空出来，从未排的工件里按规则挑一个放上去（若下一个维护必须先做就先做维护）：

- **EDD**（最早交期）：挑交期 d_j 最早的；
- **MDD**（修正交期）：挑 max(d_j, t + p_j) 最小的，t 是机器空闲时刻。交期都很宽松时等于 EDD，全部注定迟交时接近"短的先做"；
- **ATC**（表观延期代价）：优先级 = (1/p_j) · exp(−max(0, d_j − p_j − t) / (k·p̄))，取最大。离交期越近、加工越短越优先。

### 4.3 编码与解码：智能优化算法的"语言"

GA、SA、IGA 和强化学习主方法都在同一种"语言"上工作：**一个排列**，里面每个工件一个记号，每个维护窗口一个记号。
例如 3 个工件、2 台机器各 1 个窗口，排列可以是 `[工件2, 维护(M0), 工件0, 工件1, 维护(M1)]`。

**解码器**（`maintenance.metaheuristics.TokenDecoder`）从左到右读这个排列：

- 读到工件：放到**完工最早**的机器上。如果放上去会让该机器下一个维护赶不上窗口，就先插入维护，再放工件；
- 读到维护：立刻安排这次维护（固定方式在给定时刻，联合方式在"机器空闲时刻"与窗口起点中较晚的那个时刻）；
- 读完后还没做的维护，按顺序补在最后。

这些规则保证**任何排列都能解码成合法调度**，搜索时不需要修复或罚分。搜索算法要做的只是找一个好的排列。

### 4.4 GA、SA、IGA

- **GA（遗传算法）**：保持 40 个排列组成的"种群"。每一代用锦标赛选出父代，按顺序交叉（OX：保留父 A 的一段，其余按父 B 的顺序填）
  生成子代，以一定概率做变异（交换两个位置或把一个记号插到别处），保留最好的 2 个直接进入下一代。
- **SA（模拟退火）**：从按交期排序的排列出发，每次随机改动一点；变好就接受，变差也以概率 exp(−变差量/温度) 接受。
  温度从"一开始约一半的差解会被接受"逐渐降到很低，前期大胆探索、后期精细调整。
- **IGA（改进遗传算法）**：在 GA 上加两处改进：
  1. 初始种群里放入按交期、加工时间、松弛时间排序得到的 6 个好排列，而不是全靠随机；
  2. 每一代对最好的子代做 20 次"插入"局部搜索，变好就保留。

三者共用同一个评估预算（解码次数）或时间上限，返回的都是检查器接受的调度。IGA 也可以把别的方法给出的排列放进初始种群
（**热启动**，见 5.5）。

### 4.5 精确方法

- **CP-SAT**（`maintenance.cpsat`）：每个工件在每台机器上一个可选区间（恰好一个存在），每个维护窗口一个必选区间，
  同一机器上所有区间不重叠，延期变量精确等于 max(0, C_j − d_j)。小规模（n = 8 左右）能证明最优；n ≥ 50 时，G4 中 213 次证得最优的
  全是最优值为 0 的宽松实例，有正延期的 171 次全部只是限时可行（FEASIBLE）。
- **暴力枚举**（`maintenance.enumeration`）：n ≤ 5、m ≤ 3 时列举所有方案，用来独立核对 CP-SAT 模型没写错。

## 5. 毕设的强化学习主方法

### 5.1 把"排调度"变成一步一步的选择（MDP）

强化学习需要一个"环境"：每一步给出当前状态和**可选动作**，选一个，环境往前走一步，直到结束时给出好坏评价。
主方法的环境 `maintenance.sequence_env.SequenceEnv` 就是把 4.3 的解码器拆成逐步进行：

- 每一步的候选动作 = 每个还没放的工件 + 每台机器"下一个待做的维护"，最多 n + m 个；
- 选一个记号，解码器按规则把它落到调度里；
- 所有工件都放完时结束，回报 = −总延期。

这种设计让每一步的候选数随规模**线性**增长，n = 100、m = 8 时也只有约 108 个候选。

（还有一个早期环境 `maintenance.env`：动作是"工件 × 机器"组合，可以证明一定能构造出最优解，但候选数是 n × m，
只用于早期单窗口实验。）

### 5.2 策略网络：给候选打分

每个候选动作算 20 个**特征**（`SEQUENCE_FEATURE_NAMES`），例如：加工时间相对平均值、现在放它会延期多少、它的 MDD 与 ATC 值、
会不会逼出一次维护、机器剩余负荷等。时间类特征都除以"每台机器的平均工作量"，所以同一个网络能用于不同规模。

网络（`maintenance.attention_policy`）：

```text
每个候选的 20 个特征 → 线性层变成 128 维 → 3 层 Transformer 编码器（8 头注意力，候选之间互相"看"）→ 每个候选一个分数
→ 只在合法候选上做 softmax → 选择概率
```

注意力机制的作用：一个候选好不好要和其他候选比较才知道（例如另一个工件更急），注意力层让每个候选的分数参考全部候选。
非法动作根本不进入 softmax，所以策略永远只能构造出合法调度。

### 5.3 训练第一步：模仿学习（行为克隆）

先让 IGA 在 2 万个训练算例上各跑 5000 次评估，得到较好的排列，把它们拆成"每一步选了哪个记号"，作为**示范**。
网络像做选择题一样学习：给定状态，尽量把概率放在示范选择上（交叉熵损失）。训练 8 轮，取验证集上最好的一版。

只做这一步，网络能接近但很难超过老师；验证集上总延期均值约 58.5。

### 5.4 训练第二步：REINFORCE 强化学习

然后让网络自己试：

1. 每批取 16 个算例，每个算例用当前策略**随机采样** 16 个完整调度；
2. 同一算例的 16 个结果取平均作为**基线**（POMO 式共享基线）；
3. 比平均好的那些调度，把其中每一步的选择概率调高；比平均差的调低。调整幅度正比于"好多少"。

这就是策略梯度 REINFORCE。用同一算例的平均作基线，是为了消掉"这个算例本身难或易"的影响，只看选择本身的好坏。
共训练 1696 步，每 20 步在验证集上评估一次，保留最好的检查点。验证集总延期从 58.5 降到约 52，
比老师 IGA-5000（53.9）还好。没有使用 PPO、价值网络等更复杂的技术。

### 5.5 使用方式

- **贪心**：每步选分数最高的候选，跑一遍即得一个调度（n = 100 时 GPU 上约 0.3 秒）；
- **采样 K 次取最好**：按概率随机跑 K 遍，取最好的，时间多一些、质量好一些；
- **RL 热启动 IGA**（G5）：把贪心 + 16 次采样得到的不同排列放进 IGA 的初始种群，剩下的时间交给 IGA 继续改进。
  这结合了"RL 快速给出好起点"和"搜索持续改进"两者的长处。

### 5.6 结论（G4、G5）

- n = 100、0.2–2 秒的时间预算内（RL 按 GPU 计时），RL 优于 IGA 和 SA；n = 50 时相当；n = 20 和长时间预算时 SA/IGA 更好；
- 强化学习这一步有实际作用：相对只做模仿，贪心解的总延期降低约 11%；
- RL 热启动 IGA 在 n = 100 的 1 秒以后、n = 200 的 10 秒时是所有方法中最好的；n = 50 时 1 秒最好，
  10 秒时 SA（gap 0.008）略好于它（0.009–0.012）；
- 联合维护比固定维护平均降低总延期：G4 中 n = 20/50/100 分别约 49%/11%/7%，窗口越宽收益越大。

读这些检验结果时要注意：测试实例按因子网格生成，同一 `(n, 实例种子)` 下的所有案例共用同一份加工时间和交期分位数，
不是独立样本，p 值偏乐观；G4 的检验没有做多重校正，G5 的预先登记检验做了。详见 [当前进度](../START_HERE.md) 的"已知局限"。

详见 [G4 结论](../experiments/results/g4_summary/findings.md)、[G5 结论](../experiments/results/g5_summary/findings.md)
与 [计时核查](../experiments/results/g5_iga_retime_check/findings.md)。

## 6. 大创：AGV 搬运与有限缓冲

### 6.1 问题

在柔性作业车间（第 2 节）的基础上加入物流：

- 工件放在 **L/U 站**（装卸站），要由 **AGV**（自动导引小车）运到机器，工序之间换机器也要运，最后可能还要运回 L/U 站；
- 小车**单载**（一次只拉一个工件），去取货时要先**空驶**过去，再**载货行驶**；行驶时间由车间布局的距离矩阵决定；
- 每台机器前有一个容量为 B 的**输入缓冲**，加上机器本身，同时最多容纳 1 + B 个工件；
- **加工后阻塞**：工件加工完后留在机器上，直到被小车取走，机器才能做下一个；
- 目标：makespan 最小。

缓冲小加上阻塞，可能出现**死锁**：例如机器 A 上的工件要去 B，B 上的工件要去 A，两边都满了，谁也动不了。

### 6.2 事件仿真器与规则

`logistics.simulator` 按时间推进：每当有事情可以做（有空车、有工件可运），就让决策者从**候选**里选一个：
"用车 v 把工件 j 运到机器 m"，或"工件留在本机继续做下一道"。机器在派车时就锁定，并在目的地预留一个位置。

规则（`logistics.rules`）：

- **联合规则 EFT**：同时考虑空驶、载货行驶、目的机器排队，选预计完工最早的"工件—机器—车辆"组合；
- **解耦规则**（FIFO/SPT/MWKR + NV）：先当作运输不花时间，按规则选工件和机器；再派最近的空车。
  这模拟了"先排生产、再调度车辆"的常见做法。

### 6.3 前瞻式死锁规避

规则选中一个动作后，先在仿真器的**副本**上执行它，再用一个保守的策略把剩下的全部推演完
（先把已进车间的工件推完，车间清空后才从 L/U 放行下一个）。推演能完成，说明执行这一步后一定还有出路，才真正执行；
否则换规则的下一个偏好，都不行就等待。推演成功是"安全"的证明；推演失败不一定代表真会死锁，所以这种规避偏保守。
大算例上 420 次运行全部得到合法调度，而普通规则在无缓冲时几乎全部死锁。

### 6.4 参考方法

- **CP-SAT**（`logistics.cpsat`）：小算例上可证最优，用来衡量规则与学习策略离最优多远；
- **解耦基线**（`logistics.decoupled`）：先用 CP-SAT 只排机器，再固定机器方案、只优化车辆。用来量化"联合决策"的价值；
- **SA / GA**（`logistics.metaheuristics`）：编码为工序顺序、机器分配、运输顺序、车辆分配四部分，用序列解码器求最早时间表；
  顺序矛盾时退回"仿真 + 死锁规避"解码。大算例上以 SA 为参考。

### 6.5 结论（L1）

- 模型与公开基准一致：10 个参考解重放后 makespan 全部复现；
- "先排机器再派车"比联合优化差约 5%–10%，阻塞且无缓冲时差 17%–20%，并且有 2–3 成的机器方案根本无法执行；
- 缓冲越小越差：以 SA 为参考，缓冲无限 / 2 / 1 / 0 时 makespan 分别比基准约定高 4% / 3% / 9% / 41%。

## 7. 大创的强化学习策略（L2）

`logistics.policy`，与毕设主方法的思路相同，但网络更小、用 NumPy 实现：

- **决策点**：仿真器每次需要做决定时；
- **候选与特征**：每个候选一行 20 个特征（是否原地留下、空驶/载货时间、预计完工时刻及其排名、目的工位占用、车辆空闲数等）；
- **网络**：两层感知机（20 → 32 → 1），共 704 个参数，给每个候选打分，softmax 得概率；
- **死锁规避作为掩码**：选中的候选先用 6.3 的前瞻推演检查，不安全就屏蔽、在剩下的候选上重新归一化；
- **训练**：先模仿"4 条规避规则中在该算例上最好的那条"的决策，再用 REINFORCE（同一算例多次采样的平均作基线）；
  只用验证集选检查点；3 个训练种子。

结论（L2 正式测试，测试集只用一次）：预先登记的 4 个假设在 3 个种子上全部成立；大算例上采样 32 次比逐算例最好规则好约 16%，
比大预算 SA 好约 10%；小算例上距证得最优约 12.5%；无缓冲（B = 0）时最弱。

## 8. 怎样公平地比较算法

### 8.1 质量—时间曲线

不同方法用时差别很大（规则毫秒级，SA 跑多久都行），只比较"最终结果"不公平。G4/G5 的做法是：
给定时间预算 t（0.05 秒到 10 秒共 8 档），每种方法取"在 t 之前已经得到的最好解"。还没给出任何解的记为"无解"。
这样能画出每种方法"质量随时间变化"的曲线，看出谁在什么时间段占优。

### 8.2 gap

每个算例的 **best-known** = 所有方法、所有运行中找到的最小总延期。
**gap** = (T − best-known) / max(1, best-known)，表示比已知最好解差多少（0 表示追平）。分母取 max(1, ·) 是为了
best-known 为 0 时不除以 0；代价是 best-known 很小的算例上 gap 会被放大（G5 的 H5 就遇到了，见其 findings）。

### 8.3 统计检验

- **配对 Wilcoxon 符号秩检验**：同一个算例上两种方法配成一对，看差值的正负和大小排序，判断一方是否系统性地更好。
  它基于秩，不受个别极端值左右；差值为 0 的配对不参与。
- **Holm 校正**：同时检验多个假设时，单独看每个 p 值会高估"显著"的机会，Holm 方法把 p 值按顺序放大，控制整体误判率。
- **多种子规则**：强化学习结果受训练随机性影响，G5 训练了 3 个种子，规定"至少 2 个种子满足才算假设成立"。

### 8.4 预先登记与如实报告

每批正式实验先写**协议**（`docs/protocols/`）：要检验哪些假设、用哪些算例、怎么计时、怎么判定，再运行。
结果不论好坏都按协议报告；看到结果之后才想到的分析一律标为**探索性**，不能当作预先证实的结论。
计时实验运行时机器上不能有其他重任务；G4、G5 都专门核查过计时干扰（见各 findings）。
