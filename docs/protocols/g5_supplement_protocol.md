## 5. 评价方法

每个测试实例上：

| 方法 | 设置 |
|---|---|
| EDD、MDD、ATC | 一次构造 |
| IGA | 一次 10 s 运行（种子 0），记录 best-so-far 轨迹 |
| SA | 每个时间预算单独运行一次（其降温依赖预算），种子 0 |
| RL（3 个种子各一个模型） | 贪心 1 次，再采样 4、16、64 次（GPU 计时，同 G4）；另报单线程 CPU 的贪心与采样 4 次 |
| 只模仿（3 个种子） | 贪心 1 次，采样 16 次 |
| **RL + IGA**（E3，3 个种子） | 先用该种子的 RL 做贪心 + 采样 16 次，把其中互不相同的序列（最多 40 个，即种群规模）放入 IGA 初始种群，其余个体按 IGA 原方式生成；IGA 运行到总时长 10 s。轨迹时间 = RL 推理时间 + IGA 已用时间 |
| CP-SAT | 只用于 G5-T 的 n = 20 实例，60 s |

- **任一时间预算 t 下的取值**：沿用 G4 的定义（`g9_g4_summary.py`）。RL 取在 t 之前完成的各个推理点的最好值；
  搜索方法取轨迹中 t 之前的最好值；t 之前尚未得到解的记为"无解"，不参与该点的配对检验。
- **时间预算**：t ∈ {0.05, 0.1, 0.2, 0.5, 1, 2, 5, 10} s。
- **best-known**：每个实例取所有方法、所有种子、所有运行中的最小总延期；
  gap = (T − T\*) / max(1, T\*)。
- **计时口径**（同 G4）：
  - 搜索方法：单实例、单进程 CPU，2 个进程并行，本机无其他负载；
  - RL：一次一个实例，计入特征计算、环境步进和最终检查。
- 所有调度都过检查器，被拒绝的结果直接终止实验。

## 6. 预先登记的假设

按训练种子分别检验：单侧配对 Wilcoxon 符号秩检验；每个种子内对 H1–H5 做 Holm 校正，α = 0.05；
**3 个种子中至少 2 个满足即成立**。

| 编号 | 假设 | 测试集与时间 |
|---|---|---|
| **H1**（复现 G4 的探索性发现） | RL 的 gap 小于 IGA | G5-T，n = 100，t = 1 s |
| **H2**（REINFORCE 的作用） | RL 贪心的总延期小于只模仿模型的贪心 | G5-T 全部 576 个实例 |
| **H3**（热启动，长预算） | RL + IGA 的 gap 小于 IGA | G5-T 全部实例，t = 10 s |
| **H4**（热启动，短预算） | RL + IGA 的 gap 小于 IGA | G5-T 全部实例，t = 1 s |
| **H5**（规模推广） | RL 的 gap 小于 IGA | G5-L，t = 2 s |

**描述性结果**（不做检验）：
- 各方法按规模的质量—时间曲线，3 个种子分别画出；
- 种子之间的差异：每个时间预算下 3 个种子 gap 的极差；
- 只模仿与 RL 在不同采样次数下的差距；
- RL + IGA 与纯 RL、纯 IGA、SA 按规模比较，尤其是 n = 20；
- G5-L 上各方法在各时间预算下的 gap 与"无解"比例（n = 200 时 RL 的单次推理可能超过 0.2 s）；
- 协同维护（联合相对固定）的总延期降低，按规模与 β 分解，与 G4 对照。

**报告规则**：每个假设不论成立与否都写出；3 个种子的结果都列出；看到结果后补做的分析一律标为"探索性"。

## 9. 批准后、运行前的修改记录

1. **训练参数**：`g6_attention_policy.py` 的命令行默认值与 G4 实际运行不同（例如 REINFORCE 批大小默认 32、评估间隔默认 10、时长上限默认 120 分钟）。
   G5 训练显式传入 G4 种子 0 的 summary 中记录的全部参数：
   `--bc-epochs 8 --bc-batch 1024 --bc-lr 1e-3 --rl-steps 100000 --rl-batch 16 --rl-samples 16 --rl-lr 1e-4 --eval-every 20 --eval-batch 100 --workers 6 --max-minutes 240`，只改 `--seed`。
2. **热启动的序列数**：贪心 + 16 次采样最多给出 17 个不同序列，不会达到 40 的上限；IGA 种群的其余个体照常由启发式序列和随机序列补齐。
3. **RL + IGA 的计时**：RL 推理（PyTorch 环境，GPU，`g8 --save-sequences`）与 IGA（项目环境，CPU，`g11`）分两步运行，
   轨迹时间 = 记录的 RL 推理时间 + IGA 已用时间。两步中间的数据读写不计时。
4. **CP-SAT 只用于 n = 20**：通过 `g7 --cpsat-max-tasks 20` 实现；G5-L 不跑 CP-SAT。
5. 汇总脚本 `g12_g5_summary.py` 中，单侧 Wilcoxon 检验去掉差值为 0 的配对（scipy 的默认做法）；全部配对差值都为 0 时记 p = 1。

**2026-11-05 内存问题与修改（第 6 条已实施；第 7–8 条用户 2026-11-05 批准）**

2026-11-04 夜间的 7 次训练都在约 23 分钟（模仿结束、REINFORCE 开始）因可用内存低于 1.2 GB 被保护脚本停止，没有产生结果。
诊断运行（`experiments/runs/diag_g6_memory*`，不归档）测得：
- 回放阶段：主进程合并教师状态时同一份 1.85 GB 数组同时存在三份，加上 6 个回放进程约 3 GB；
- REINFORCE 阶段：按 4096 个状态分块重算时显存用满（7.9 GB），另有约 4.3 GB 溢出到系统内存（Windows 共享显存），进程工作集升到 5.4 GB。
  G4 种子 0 当时在空闲机器上运行，每步约 7.8 s，很可能也发生了同样的溢出，只是内存足够没有出错。

6. **合并教师状态时边复制边释放**（`StateDataset.concatenate`）：结果与原实现逐位相同（新增等价性测试）。
7. **回放进程 6 → 3**、**REINFORCE 分块 4096 → 1024 个状态**（`g6 --chunk-rows`）：只改变内存与速度，不改变训练目标；
   分块大小只影响浮点求和顺序（已有测试保证不同分块的梯度在舍入误差内一致）。诊断中显存降到 2.7 GB、无溢出，
   每步约 4.2 s（含评估），比 G4 快约一半。
8. **REINFORCE 改为固定步数**：因为每步更快，若仍按 240 分钟截止，种子 1、2 会比种子 0 多训练约 80% 的步数，三个种子不再可比。
   改为 `--rl-steps 1696`（G4 种子 0 在 240 分钟内实际完成的步数），`--max-minutes 480` 只作保险。
