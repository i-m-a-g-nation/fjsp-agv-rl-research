## 已有检查器怎样发现问题

单机按 A、B 顺序加工；两任务加工时间均为 2，交期为 2、4；必需维护时长 2，完整维护区间必须在 `[0,6)` 内。

| 维护区间 | A / B 加工区间 | 重算总延期 | 现有维护检查器结果 |
|---|---|---|---|
| `[0,2)` | `[2,4)` / `[4,6)` | 4 | 接受所报 4 |
| `[2,4)` | `[0,2)` / `[4,6)` | 2 | 拒绝所报 0：`TOTAL_TARDINESS_MISMATCH` |
| `[4,6)` | `[0,2)` / `[2,4)` | 0 | 接受所报 0 |

最后一行是离线构造并通过现有检查器的正确见证，不是模型输出。总延期非负，所以该见证也证明本题可达到最小值 0。没有调用新优化器或修改原检查器。

诊断脚本最初只按“延期/tardiness”关键词识别目标，误判了正确的 LaTeX 公式；离线复核已纠正这一判定。原始模型输出和初始诊断保留不改，纠正另写入 `offline_review.json`。纠正后总体仍未通过，不能把脚本的误判和模型的实际错误混为一谈。
